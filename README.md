# TFT Set 18 — AP / AD Champion & Comp Reference

A player-facing guide for Teamfight Tactics Set 18 that auto-updates champion stats,
item data, and meta comps without requiring manual HTML edits.

## Live site

Deployed on Vercel at [https://tft-guide.vercel.app](https://tft-guide.vercel.app).

---

## Architecture

```
data/               ← source-of-truth JSON (auto-updated by scripts)
  champions.json
  items.json
  comps.json
  scores.json         ← generated by api/vote-scores.js via GH Actions

scripts/            ← data-ingestion scripts (run by GitHub Actions)
  fetch-champions.js  → pulls Riot Data Dragon, classifies AP/AD
  fetch-comps.js      → pulls tactics.tools, promotes community comps

api/                ← Vercel Edge Functions (player-feedback backend)
  vote.js             POST /api/vote         — thumbs up/down a comp
  vote-scores.js      GET  /api/vote-scores  — return score map for GH Actions
  submit-comp.js      POST /api/submit-comp  — submit a community comp
  pending-comps.js    GET  /api/pending-comps — return submissions with ≥3 votes

template/
  page.html           ← HTML template with `// __INJECT_DATA__` placeholder

build.js            ← reads JSON + template, outputs dist/index.html
dist/index.html     ← built output served by Vercel

.github/workflows/
  daily-refresh.yml   ← runs daily: fetch → build → auto-commit or open PR
```

## Local development

```bash
# (Re)build the page from current data files
node build.js            # → dist/index.html

# Refresh champion data from Riot Data Dragon
node scripts/fetch-champions.js

# Refresh comp stats from tactics.tools + community votes
node scripts/fetch-comps.js

# All three in one go
npm run refresh
```

Open `dist/index.html` in a browser — no server needed.

## Automated update pipeline

A GitHub Actions workflow (`.github/workflows/daily-refresh.yml`) runs every day at 06:00 UTC:

1. **Fetch champion data** — calls Riot Data Dragon (`ddragon.leagueoflegends.com`), merges new
   champions, classifies AP / AD by keyword rules, and writes `data/champions.json`.
2. **Fetch comp stats** — calls `tactics.tools` for placement stats (Diamond+), matches them to
   comps by unit overlap, and checks `api/vote-scores` for community vote signals.
3. **Rebuild** — `node build.js` regenerates `dist/index.html` from the updated JSON.
4. **Deploy decision**
   - Stats-only change → auto-commit to `main` and Vercel deploys.
   - New champions detected → a PR is opened for human review of AP/AD classification.

### What still needs a human

| Situation | Why |
|-----------|-----|
| New Set / new champions | AP/AD classification may be ambiguous |
| Ability descriptions | Data Dragon text may be too terse |
| Set name / page title change | Confirm before shipping |

Everything else — placement stats, tier order, community comp inclusion — is automated.

## Player feedback (Vercel Edge Functions)

Four Edge Functions in `api/` enable player-driven quality signals.
They require a **Vercel KV** database (free tier is sufficient).

### Setup

1. In the Vercel dashboard, create a KV store and link it to this project.
2. Vercel automatically injects `KV_REST_API_URL` and `KV_REST_API_TOKEN`
   as environment variables — no manual work needed.
3. Add `SITE_URL` as a Vercel project variable (e.g. `https://tft-guide.vercel.app`)
   — used by `scripts/fetch-comps.js` to call `api/vote-scores` and `api/pending-comps`.

### Endpoints

| Method | Path | Purpose |
|--------|------|---------|
| `POST` | `/api/vote` | Thumbs up / down a comp. Body: `{ comp, vote, patch }` |
| `GET` | `/api/vote-scores?patch=X` | Returns `{ "comp-slug": netScore }` map |
| `POST` | `/api/submit-comp` | Submit a new community comp |
| `GET` | `/api/pending-comps?patch=X` | Returns submissions with ≥ 3 votes |

## Data files

All data files are plain JSON and can be hand-edited when needed.

### `data/champions.json`

Each champion object:
```json
{
  "n": "Ahri", "c": 4, "r": "ap",
  "t": ["Rebel", "Mage"],
  "a": "Orb of Deception",
  "d": "Fires an orb dealing magic damage.",
  "hp": 850, "ms": 330, "mm": 600,
  "ad": 55, "ar": 35, "mr": 35,
  "img": "ahri"
}
```

`r` is the damage type: `"ap"`, `"ad"`, or `"fx"` (flex / adaptor).

### `data/comps.json`

Each comp object:
```json
{
  "n": "Rebel Carry",
  "style": "Standard",
  "diff": "Easy",
  "k": "hy",
  "src": "meta",
  "place": 4.2, "top4": 62, "win": 18, "pick": 8,
  "board": ["Jinx", "Ekko", "Malphite", "Lux", "Vi", "Jayce", "Fiora"],
  "carries": ["Jinx"],
  "carryItems": { "Jinx": ["Runaan's Hurricane", "Last Whisper", "Giant Slayer"] },
  "when": ["Strong opener available", "Early rebel units"],
  "tips": ["Level 8 for 6 Rebels"],
  "slug": "rebel-carry"
}
```

## Contributing

- To fix champion data: edit `data/champions.json` and run `node build.js`.
- To add a meta comp: edit `data/comps.json` and run `node build.js`, or submit via the in-page form.
- For structural issues (AP/AD misclassification): open an issue or PR against `data/champions.json`.
